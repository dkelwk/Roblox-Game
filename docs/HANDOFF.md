## 5. Setup on the Mac

Full steps: [STUDIO_SETUP.md](STUDIO_SETUP.md).

1. **Studio:** update to the latest version. Enable **Assistant → ⋯ → Manage MCP Servers →
   Enable Studio as MCP server**, then quick-connect your Claude client (Claude Desktop or
   Claude Code).
2. **Repo tooling** (needed to build, test or edit code): Git, then Rokit (one install
   command), then in the clone `rokit install` (approve each tool once) and
   `rojo plugin install`.
   - Pinned versions (`rokit.toml`): Rojo 7.7.1, Lune 0.10.5, Selene 0.31.0, StyLua 2.6.0,
     luau-lsp 1.70.1.
3. **Claude with repo access:** run Claude Code (or the Claude Desktop app's local coding
   session) **in the cloned folder**. It reads `CLAUDE.md` automatically. A chat-only Claude
   Desktop session connected to Studio can inspect Studio but can't run the build or commit;
   attach this file to it.

## 6. What the new session must know

### Ground rules

1. **Never touch the original live game.** Only the dev place is open while an MCP client
   is connected, because MCP clients can read and modify any open place.
2. **The repo is the source of truth.** Studio is for inspection and testing.
   - Any change made in Studio (scripts or world) must be made in the repo, or it is lost
     on the next build or Rojo sync. Rojo syncs repo → Studio only.
   - `Workspace.World` is **generated** by `src/tooling/WorldBlockout`. Fix world issues in
     the generator (positions in `src/shared/Config/WorldLayout.luau`), then run
     `lune run scripts/build`. Never hand-edit the world except for throwaway experiments.
3. **No Phase 1 work yet.** Finish [STUDIO_VERIFICATION.md](STUDIO_VERIFICATION.md) first.
4. **Before every commit,** `lune run scripts/check` must end with `✓ All checks passed`.
   StyLua occasionally needs two passes (`stylua src scripts tests` twice).
5. **Report honestly:** say what was verified in Studio, what was only verified offline, and
   what is untested. Use screenshots for visual claims.
6. **Every asset follows the stylized low-poly direction** ([ART_DIRECTION.md](ART_DIRECTION.md)).
   Every number lives in a config module, and the server is authoritative.

### Creative-director decisions already applied

- **Hybrid spawning:** starter capsules are `PerPlayer`. `Shared` is reserved and the
  validator rejects it until it's built.
- **Secret spots:** hidden capsule spawns only.
- **Zib:** stays purple. Rarity never changes appearance.
- **First discovery:** Glorp is guaranteed on a new player's first successful scan, using a
  persisted flag written in the same save as the specimen.
- **Spawns** face the Extraction Gate.
- **Visual style:** stylized low-poly.

### Known quirks

- **Lune 0.10.5 bug:** `CFrame.lookAt` (and the two-Vector3 `CFrame.new`) mirror the
  look direction's Z axis. `scripts/lib/Runtime.luau` gives every script run under Lune a
  Roblox-accurate replacement, guarded by `tests/Harness.spec.luau` and the world
  orientation specs. Never "compensate" in game or generator code; real Roblox is correct.
- **Wedge orientation is assumed, not seen:** WedgePart's vertical face at +Z, slope
  descending toward −Z. This affects the Nest Ridge ramp, the talus and the console screens.
  If the ramp shows as a cliff in Studio, flip its yaw in `DesertRegion.buildNestRidge` and
  re-run the build.
- **Generated on first run:** `roblox.yml` (Selene's Roblox std) and
  `build/globalTypes.None.d.luau` (downloaded by `scripts/check`). Both are gitignored.

### Not yet verified (check these first in Studio)

- Lighting, Atmosphere and Bloom; Neon intensity; SurfaceGui sign legibility.
- Ramp direction; walkability of slopes and dunes; collisions (curtain passable, walls,
  fences and glass solid); truss climbable.
- Spawn view and camera space in front of the labs.
- Streaming behavior of Atomic plots and Persistent landmarks.
- `Main.client` running.
- FBX import (scale, pivot, faceted shading, 11 MeshParts bound by `AssetBinder`).
- Mobile frame times; draw calls and triangles (Scene Analysis).
